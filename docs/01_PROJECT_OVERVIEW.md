# 01. Обзор проекта FSP Talent

Документ для жюри и новых участников команды. Описывает проблему, решение и отличие от классического рекрутинга по **фактически реализованному** коду репозитория LCT_Resonance.

Связанные материалы: `02_FUNCTIONAL_REQUIREMENTS.md`, `03_ARCHITECTURE.md`, `17_DEMO_SCENARIOS.md`, корневой `README.md`, `APPROACH.md`, `CJM.md`.

---

## 1. Название и контекст

**Название продукта:** FSP Talent (в репозитории также встречается имя LCT Resonance / Resonance).

**Конкурс:** специальный трек хакатона ЛЦТ / Федерации спортивного программирования (ФСП).

**Суть:** цифровая платформа обратного рекрутинга (reverse recruitment) для ИТ-специалистов с подтверждением профессионального грейда тестированием и опциональным учётом достижений ФСП.

**Источник ТЗ:** файл «ФСП спец. трек ТЗ» в рабочем пространстве на момент подготовки документации **не обнаружен**. Требования восстановлены из реализованного кода и внутренних спецификаций команды (`Backend.md`, `Frontend.md`, `ML.md`, `APPROACH.md`). Там, где формулировка ТЗ цитируется в этих файлах, она помечена как «по внутреннему ТЗ команды».

---

## 2. Проблема

Классический поиск ИТ-специалистов опирается на резюме и совпадение ключевых слов.

| Боль | Что происходит на рынке | Следствие |
| ---- | ----------------------- | --------- |
| Шум откликов | Сотни нерелевантных резюме на вакансию | HR тратит время на первичный отсев |
| Самооценка грейда | «Middle» в анкете ничем не подтверждён | Техническое интервью становится единственной проверкой |
| Раннее раскрытие контактов | Телефон и почта доступны до взаимного интереса | Спам, утечка персональных данных |
| Непрозрачный матчинг | «Чёрный ящик» рекомендаций без объяснений | Нет доверия к выдаче |

Участники соревнований ФСП имеют измеримые достижения, но на обычных job-бордах этот сигнал почти не используется. При этом платформа **не** ограничивается только ими: отсутствие истории ФСП не исключает кандидата из подбора.

---

## 3. Предлагаемое решение

FSP Talent реализует обратную механику:

1. Кандидат регистрируется, заполняет профиль, выбирает специализацию и предполагаемый грейд.
2. Проходит тестирование; при балле ≥ 70 получает **подтверждённую категорию** (специализация + грейд).
3. Попадает в Talent Pool работодателей, у которых вакансия совпадает с этой категорией.
4. Работодатель описывает потребность (вакансия), получает ранжированную подборку с Match Score и причинами.
5. Отправляет персональное приглашение (оффер) с зарплатой в рублях.
6. Кандидат принимает или отклоняет предложение.
7. Контакты кандидата раскрываются работодателю **только после принятия** (или собственного отклика на вакансию) — решение принимается на Backend.

Дополнительно: цифровой карьерный паспорт (публичная ссылка при согласии), синхронизация достижений ФСП через адаптер (на хакатоне — mock), shortlist, сравнение кандидатов, каталог вакансий с откликами, административная панель.

---

## 4. Целевая аудитория

### Кандидаты

- Junior / Middle / Senior (и Intern / Lead в справочнике) в поддерживаемых специализациях.
- Участники соревнований ФСП и специалисты без истории ФСП.
- ИТ-специалисты с коммерческим опытом, готовые подтвердить грейд тестом.

### Работодатели

- ИТ-компании и продуктовые команды.
- HR и технические руководители, которым нужна отфильтрованная подборка с объяснимым score.

### Администратор платформы (дополнительный модуль)

- Операционный контроль пользователей, офферов, вакансий, обзора системы.
- Не является обязательным ролевым кабинетом исходного конкурсного сценария, но реализован в MVP.

---

## 5. Ключевое отличие: Reverse Recruitment

В классической модели кандидат **обязан** первым откликнуться. В FSP Talent:

- работодатель сам находит подходящую категорию и конкретного специалиста;
- оффер с зарплатой уходит адресно;
- создание опубликованной вакансии **не блокирует** отправку оффера (вакансия может быть в `draft`; оффер может ссылаться на вакансию или работать в контексте Talent Pool);
- кандидат видит зарплату до начала общения;
- контакты закрыты до Accept.

Именно эта механика — смысловой центр продукта и golden path автотестов (`backend/tests/integration/test_golden_path.py`, `frontend/src/shared/api/p0.dod.test.ts`).

## 6. Ценность

### Для кандидата

- Подтверждённая категория вместо голословного грейда.
- Контроль раскрытия контактов.
- Адресные предложения с вилкой в рублях.
- Опциональный сигнал достижений ФСП без обязательности участия в соревнованиях.
- Карьерный паспорт для внешней демонстрации (при согласии на публикацию).

### Для работодателя

- Пул уже отфильтрован по подтверждённой категории вакансии.
- Explainable Match Score (0–100) с плюсами и минусами.
- Персональные приглашения вместо сотен холодных откликов.
- Shortlist и compare для сравнения 2–4 кандидатов.

### Гипотезы (не измерены в проде)

Сокращение времени до первого релевантного контакта и снижение доли «шумовых» диалогов. Числовых KPI «−X% time-to-hire» в репозитории **нет** — не заявляем как факт.

## 7. Что реализовано в MVP (кратко)

| Область | Статус |
| ------- | ------ |
| Auth, email verify, RBAC | Реализовано и покрыто тестами |
| Профиль кандидата, согласия, паспорт | Реализовано |
| Тест 10 вопросов, порог 70, без автодаунгрейда | Реализовано |
| Talent Pool + Match Score + reasons | Реализовано (baseline; ML HTTP опционально) |
| Офферы, Accept/Decline, contacts gate | Реализовано |
| FSP mock adapter | Демонстрационная интеграция |
| Admin UI | Реализовано (в основном read + block users) |
| Docker compose стенд | Реализовано |
| Официальное API ФСП | Не предоставлено организаторами; real-адаптер — контрактный stub |
| Embeddings / нейросети | Не реализованы (осознанный выбор explainable rules) |

Подробная матрица — в `02_FUNCTIONAL_REQUIREMENTS.md` и `22_REQUIREMENTS_TRACEABILITY.md`.
