# Функциональные требования 

## 1. Общая задача

Frontend-разработчик отвечает за реализацию клиентской части веб-сервиса для взаимодействия кандидатов и работодателей.

Клиентская часть должна обеспечивать полный пользовательский сценарий:

**Кандидат:** регистрация → заполнение профиля → указание профессиональных навыков и карьерных предпочтений → получение/синхронизация достижений ФСП → просмотр приглашений → принятие или отклонение предложения.

**Работодатель:** регистрация → создание вакансии → поиск и фильтрация кандидатов → просмотр профиля и подтвержденных достижений → просмотр соответствия кандидата вакансии → отправка предложения с указанием зарплаты → получение ответа кандидата.

Frontend должен взаимодействовать с Backend API и не содержать бизнес-логику расчета рейтингов, результатов тестирования и Match Score.

---

# 2. Авторизация и роли пользователей

Необходимо реализовать:

- страницу регистрации;
- страницу авторизации;
- выход из аккаунта;
- хранение состояния авторизации;
- обработку ошибок авторизации;
- разграничение интерфейсов в зависимости от роли пользователя;
- защищенные маршруты для авторизованных пользователей.

Поддерживаемые роли:

- кандидат;
- работодатель;
- администратор, если административная часть входит в MVP.

После авторизации пользователь должен автоматически перенаправляться в соответствующий личный кабинет.

---

# 3. Функционал кандидата

## 3.1. Создание и редактирование профиля

Кандидат должен иметь возможность создать и редактировать профессиональный профиль.

В профиле отображаются:

- имя и основная информация;
- специализация;
- заявленный профессиональный уровень;
- опыт работы;
- профессиональные навыки и технологии;
- описание кандидата;
- желаемая должность;
- зарплатные ожидания;
- город;
- предпочтительный формат работы: удаленно / гибрид / офис;
- статус готовности к предложениям;
- результаты профессионального тестирования, если функция используется;
- достижения ФСП.

Необходимо предусмотреть статусы готовности кандидата к предложениям:

- активно ищу работу;
- открыт к предложениям;
- не рассматриваю предложения.

---

# 4. Профилирование и тестирование кандидата

Если тестирование входит в итоговый MVP, frontend должен реализовать последовательный сценарий профилирования кандидата.

Пользователь должен иметь возможность:

- выбрать профессиональную специализацию;
- указать основной технологический стек;
- указать предполагаемый грейд;
- начать тестирование;
- отвечать на вопросы;
- видеть прогресс прохождения теста;
- завершить тест;
- получить и просмотреть результат.

Для тестирования необходимо реализовать:

- экран начала тестирования;
- компонент вопроса;
- варианты ответа;
- индикатор прогресса;
- переход между вопросами;
- состояние завершения теста;
- страницу результата.

Frontend не должен получать правильные ответы на вопросы до завершения тестирования. Проверка ответов и расчет результата выполняются на Backend.

Заявленный кандидатом грейд и результат его подтверждения должны отображаться отдельно.

Например:

```javascript
```

```javascript
Заявленный уровень
Middle

Результат тестирования
82/100
Уровень подтвержден
```

# 5. Интеграция с данными ФСП

Frontend должен отображать данные об участии кандидата в мероприятиях ФСП, полученные через Backend.

Необходимо реализовать:

- запуск синхронизации данных ФСП;
- состояние загрузки данных;
- отображение полученных достижений;
- отображение даты последней синхронизации;
- обработку отсутствия достижений;
- обработку ошибки получения данных.

В карточке достижения могут отображаться:

- название соревнования;
- дисциплина;
- дата;
- результат / место;
- роль участника;
- спортивный разряд;
- другая информация, доступная через API ФСП.

Данные, полученные из ФСП, должны визуально отличаться от информации, самостоятельно указанной кандидатом.

Для подтвержденных данных необходимо использовать специальный маркер:

**«Подтверждено ФСП» / «FSP Verified».**

Frontend не должен обозначать самостоятельно введенные навыки, опыт или грейд как подтвержденные ФСП.

---

# 6. Профиль кандидата

Необходимо реализовать страницу полного профиля кандидата.

Профиль должен содержать несколько логических блоков:

- основная информация;
- специализация и профессиональный уровень;
- навыки и технологии;
- карьерные предпочтения;
- результаты тестирования;
- подтвержденные достижения ФСП;
- статус готовности к предложениям;
- зарплатные ожидания;
- формат работы.

Один и тот же профиль должен иметь разные режимы отображения для самого кандидата и работодателя.

---

# 7. Создание и управление вакансиями

Для работодателя необходимо реализовать интерфейс создания и редактирования вакансии.

Форма вакансии должна поддерживать:

- название вакансии;
- описание;
- специализацию;
- требуемый грейд;
- обязательные навыки;
- дополнительные навыки;
- зарплатную вилку;
- город;
- формат работы;
- дополнительную информацию.

Frontend должен выполнять валидацию обязательных полей перед отправкой данных на Backend.

Также необходимо реализовать:

- список вакансий работодателя;
- просмотр вакансии;
- редактирование вакансии;
- отображение статуса вакансии.

---

# 8. Talent Pool

Основным интерфейсом работодателя должен быть каталог IT-специалистов.

Работодатель должен иметь возможность просматривать доступных кандидатов в виде списка или карточек.

Карточка кандидата должна содержать:

- имя;
- специализацию;
- грейд;
- основные навыки;
- наличие подтвержденных достижений ФСП;
- статус готовности к предложениям;
- Match Score при подборе под конкретную вакансию;
- основные причины соответствия вакансии.

Из карточки должен быть доступен переход в полный профиль кандидата.

---

# 9. Поиск и фильтрация кандидатов

Frontend должен предоставить работодателю интерфейс поиска кандидатов.

Необходимо реализовать фильтрацию минимум по следующим параметрам:

- специализация;
- грейд;
- технологический стек;
- формат работы;
- зарплатные ожидания;
- дисциплина ФСП;
- наличие достижений ФСП;
- статус готовности к предложениям.

При изменении фильтров frontend должен формировать соответствующий запрос к Backend и отображать полученный список кандидатов.

Необходимо предусмотреть состояние, когда подходящие кандидаты не найдены.

---

# 10. Match Score и ранжирование

Для выбранной вакансии frontend должен отображать кандидатов в порядке релевантности.

Для каждого кандидата необходимо отображать:

- итоговый Match Score;
- совпавшие навыки;
- навыки, которые не указаны в профиле;
- соответствие специализации;
- соответствие грейда;
- соответствие формату работы;
- релевантные достижения ФСП;
- другие причины попадания кандидата в выдачу.

Пример:

```javascript
```

```javascript
Match 91%

Почему подходит:

✓ совпадает специализация Frontend
✓ React и TypeScript указаны в профиле
✓ подходит формат Remote
✓ есть релевантные достижения ФСП

Не указано в профиле:
Jest
```

Необходимо использовать формулировку **«навык не указан в профиле»**, а не утверждать, что кандидат не обладает этим навыком.

Расчет Match Score и формирование ranking выполняются Backend/ML-модулем. Frontend отвечает только за передачу параметров и визуализацию результата.

---

# 11. Просмотр кандидата работодателем

Работодатель должен иметь возможность открыть подробную карточку кандидата.

Необходимо отображать:

- специализацию;
- грейд;
- стек;
- профессиональный опыт;
- карьерные предпочтения;
- подтвержденные достижения ФСП;
- результаты тестирования;
- Match Score;
- причины соответствия вакансии.

Контактные данные кандидата должны быть скрыты до момента, предусмотренного бизнес-логикой сервиса.

---

# 12. Shortlist кандидатов

Работодатель должен иметь возможность сохранить интересующего кандидата в shortlist.

Frontend должен реализовать:

- кнопку добавления кандидата;
- удаление кандидата из shortlist;
- визуальное состояние добавленного кандидата;
- отдельный список сохраненных кандидатов.

Функция относится к дополнительным возможностям и может быть реализована после основного пользовательского сценария.

---

# 13. Отправка предложения кандидату

Работодатель должен иметь возможность отправить выбранному кандидату конкретное предложение.

Форма предложения должна содержать:

- вакансию;
- название позиции;
- компанию;
- зарплатную вилку;
- формат работы;
- сообщение кандидату.

Зарплатная вилка должна быть явно отображена в предложении.

После успешной отправки frontend должен отображать соответствующий статус.

---

# 14. Входящие предложения кандидата

В личном кабинете кандидата необходимо реализовать раздел с полученными предложениями.

Карточка предложения должна отображать:

- компанию;
- должность;
- зарплату;
- формат работы;
- текст предложения;
- дату получения;
- статус.

Кандидат должен иметь возможность:

- открыть предложение;
- принять его;
- отклонить его.

Статусы предложения:

```javascript
```

```javascript
Новое
Просмотрено
Принято
Отклонено
```

После действия интерфейс должен обновлять статус без необходимости повторного прохождения сценария.

---

# 15. Раскрытие контактных данных

До принятия предложения контактные данные кандидата должны быть скрыты от работодателя.

Frontend должен отображать соответствующее состояние:

```javascript
```

```javascript
Контактные данные скрыты

Контакты будут доступны после того,
как кандидат примет предложение.
```

После принятия предложения интерфейс должен отобразить контактную информацию, которую разрешено получить согласно Backend API.

Проверка права доступа к контактам должна выполняться на Backend. Скрытия элементов только на уровне интерфейса недостаточно.

---

# 16. Функционал вакансий для кандидата

В рамках расширенного MVP может быть реализован классический сценарий поиска вакансий.

Кандидат получает возможность:

- просматривать список вакансий;
- фильтровать вакансии;
- открывать подробное описание;
- видеть соответствие вакансии своему профилю;
- отправлять отклик.

Данный функционал является дополнительным по отношению к основному сценарию обратного рекрутинга.

---

# 17. Dashboard

При наличии времени необходимо реализовать информационные панели.

Для кандидата могут отображаться:

- количество просмотров профиля;
- количество полученных предложений;
- количество принятых предложений;
- статус профиля;
- статус синхронизации ФСП.

Для работодателя:

- количество найденных кандидатов;
- количество кандидатов в shortlist;
- количество отправленных предложений;
- количество принятых предложений.

---

# 18. Состояния интерфейса

Для основных компонентов необходимо предусмотреть следующие состояния:

- загрузка;
- успешное получение данных;
- отсутствие данных;
- ошибка;
- недоступность действия;
- успешное выполнение действия.

Например, для интеграции ФСП:

```javascript
```

```javascript
Загрузка:
Получаем данные ФСП...

Успешно:
Найдено 4 подтвержденных достижения.

Нет данных:
Достижения ФСП пока не найдены.

Ошибка:
Не удалось получить данные ФСП.
Попробуйте выполнить синхронизацию позже.
```

Необходимо использовать skeleton / loader там, где загрузка данных может быть заметна пользователю.

---

# 20. Интеграция с Backend

Frontend должен взаимодействовать с серверной частью через REST API.

Необходимо реализовать единый API-клиент и обработку:

- авторизации;
- access token;
- GET-запросов;
- POST-запросов;
- PUT/PATCH-запросов;
- ошибок API;
- состояния загрузки;
- отсутствия данных.

Frontend взаимодействует только с Backend API.

Архитектурная схема:

```javascript
```

```javascript
Frontend
   ↓
Backend API
   ↓
Matching / ML
   ↓
Backend
   ↓
Frontend
```

Прямое взаимодействие Frontend с ML-модулем не предусматривается.

---

# 21. Работа с тестовыми данными

Для независимой разработки интерфейса необходимо предусмотреть возможность работы с mock-данными до готовности Backend.

Mock-данные должны быть подготовлены минимум для:

- профиля кандидата;
- списка кандидатов;
- достижений ФСП;
- вакансий;
- результатов matching;
- предложений;
- результатов тестирования, если оно входит в MVP.

После готовности API mock-данные заменяются реальными запросами без изменения основной логики компонентов.

---

# 22. Дополнительные фичи

После реализации основного пользовательского сценария могут быть добавлены дополнительные возможности:

- сравнение нескольких кандидатов;
- визуальный Skill Radar;
- shortlist;
- рекомендации вакансий кандидату;
- отображение процента заполнения профиля;
- AI-разбор текста вакансии с автоматическим заполнением формы;
- публичный Career Passport кандидата;
- QR-код на публичный профиль;
- расширенная аналитика работодателя;
- повторное тестирование;
- сортировка кандидатов по различным параметрам.

Данные для интеллектуальных функций должны рассчитываться на Backend/ML, frontend отвечает за их отображение и взаимодействие пользователя с функцией.
